# Nagi UI 审美标准与检查单

本文件按用户 2026-11-17 的要求，为 Nagi 的界面定一套明确、可检查的标准，分两个阶段：

1. **第一阶段：保证下限。** 保留当前采用的 Qoder 外观作为基础，只修正可读性、秩序、一致性和可辨识度上的缺陷。用户已批准 [§9](#9-第一阶段下限修正已决定) 的全部下限修正，它们取代 [desktop.md 的 Qoder 契约](desktop.md#qoder-complete-layout-20261116)中对应的数值。
2. **第二阶段：自有风格。** 下限稳定之后，再在 [§10](#10-第二阶段自有风格方向提案) 的方向上设计 Nagi 自己的风格。该节目前只是提案，不是现行要求。

[§12](#12-补充检查清单尚未覆盖的部分) 是针对 §11.4 未验项的补充检查清单，用于修正落地后的复查。

判定原则：

- 判定看**实际渲染结果**。数值全部符合，但看起来错位、空洞、拥挤、难读或前后不一致，照样判失败。
- 本标准只管视觉与可感知的交互，不改变任何业务、Draft、作用域、unknown、不重放或退出语义。
- §9 的决定需要同步写入 desktop.md 的对应章节，由该文档的负责人修改，确保只有一个现行设计。

## 1. 审美方向

Nagi 是一个长时间开着、用来和多个 Agent 协作的桌面工作台。好的观感应该像一张整理过的书桌：东西都在该在的位置，最重要的那件最显眼，其余的退后。

要做到：

- **内容是主角。** 消息、事项、结果是画面里最"响"的部分；侧栏、页头、工具条、设置都退到背景里。
- **秩序来自对齐和留白，不来自框和颜色。** 少画线、少画框、少上色；用统一的对齐线、统一的间距节奏和字重来组织层级。
- **每个元素的身份一眼可辨。** 按钮像按钮，标签像标签，状态像状态，链接像链接。
- **同一件事在哪儿都长得一样。** 同一个动作、同一种状态、同一类面板，在任何页面都用同一种样子。
- **克制。** 一个区域只有一个视觉重点，一屏只有一个主操作，一套强调色。
- **稳定。** 加载、流式输出、状态变化、切换页面都不让东西跳动。
- **边缘情况也像设计过的。** 空、长、错、窄、断连这些状态，和正常状态一样讲究。

不要：花哨的渐变和光晕、卡片套卡片、满屏的分隔线、到处加粗、颜色当装饰、只能靠 hover 发现的功能、像调试输出的文字堆、把工程术语和内部路径展示给用户。

## 2. 七条原则与对应的看法

每条原则都配一个可以在截图上直接做的检查。

| # | 原则 | 怎么看 | 通过标准 |
| --- | --- | --- | --- |
| P1 | 内容优先 | **眯眼测试**：把截图模糊约 4px 再看 | 第一眼落在正文或本屏主操作上，不是侧栏背景、警告色或某个粗边框 |
| P2 | 秩序 | **对齐线测试**：沿每个块的左边缘画竖线 | 主内容列的左边缘竖线不超过 2 条（内容边、一级缩进）；右边缘同理 |
| P3 | 层级清楚 | **缩略图测试**：缩到 25% 看 | 能看出标题、正文、操作三层，块间距有规律 |
| P4 | 身份可辨 | **陌生人测试**：只看静止截图，指出所有能点的东西 | 不靠 hover、不靠猜就能指出全部按钮、链接、输入框，且不误认 |
| P5 | 一致 | **叠图测试**：同类页面截图以 50% 透明度叠在一起 | 标题、正文列、分组边框、按钮位置完全重合 |
| P6 | 不靠颜色传意 | **灰度测试**：把截图转成灰度 | 成功、警告、错误、选中、禁用仍可区分 |
| P7 | 克制 | **删除测试**：逐个元素问"去掉它会丢失什么" | 每个元素都有不可替代的作用；说不出的就是冗余，判失败 |

## 3. 硬性规则

每条规则都可以在截图或几何读数上判定。编号在检查记录中引用。具体数值见 §9。

### 3.1 网格与对齐

- **R-AL-1** 所有尺寸和间距取自同一刻度：`2 4 6 8 12 16 20 24 32 40 48`。其他值只能是某个组件内部的固定尺寸，且全局只有这一个用法。
- **R-AL-2** 每个视图的主内容列只有一条主左边缘：页头标题、消息正文、活动摘要、空态、横幅文字、composer 输入文字都落在这条线上，误差为 0。确有层级的缩进全视图只用一种（12 或 16）。
- **R-AL-3** 主内容列的右边缘同样唯一：用户气泡、表格、代码块、composer 右边界对齐；消息操作图标放在固定槽位，不随消息长短漂移。
- **R-AL-4** 侧栏里的分类标题、搜索框、列表行文字共用一条左边缘。
- **R-AL-5** 同一行里图标与文字按视觉中心对齐。
- **R-AL-6** 同类页面的骨架完全重合：切换 Settings 各分类、切换各右侧详情时，标题的 x／y、正文列宽、滚动条位置一个像素都不变。
- **R-AL-7** 任何内容都遵守所在面板的内边距；输入框、标题、按钮不贴分隔线、窗口边缘或面板边框。
- **R-AL-8** 宽窗口下内容列居中且有最大宽度，两侧留白对称；文字行长约 60–90 个英文字符或 30–45 个汉字。

### 3.2 间距与节奏

- **R-SP-1** 同组内间距 < 组间距 < 区块间距，三者至少相差一级刻度。
- **R-SP-2** 同级元素的间距在整页一致。
- **R-SP-3** 容器四周内边距对称：不能左右 24、底部只有 8。composer、横幅、分组框都要检查。
- **R-SP-4** 可滚动区域最后一项与底边至少 32；不足一屏时不出现莫名的大块空白。
- **R-SP-5** 嵌套圆角：内层圆角 = 外层圆角 − 间距（不小于 2）。
- **R-SP-6** 不出现无内容的大块空带。例如窄栏模式下为标题栏预留的高度，只能是系统要求的安全区，不能横跨整个窗口留出一条空白。

### 3.3 字体排印

| 角色 | 字号／行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面标题 | 20／28 | 600 | 每页唯一：Settings 分类、主区页面 |
| 区块标题 | 16／24 | 600 | 详情面板标题、大章节 |
| 正文 | 14／24 | 400 | 消息、阅读、长说明 |
| 控件与标签 | 13／20 | 400；按钮、选中项、对象名 500 | 按钮、输入、列表行、偏好标签、页头联系人名 |
| 辅助 | 12／18 | 400 | 时间、来源、说明、分组标题、状态 |
| 代码 | 13／20 等宽 | 400 | 仅代码与原文 |

- **R-TY-1** 最小字号 12。承载信息的文字都不小于 12。
- **R-TY-2** 字重只表达层级：600 只给标题，500 只给按钮、选中项、对象名。元数据、活动摘要、模型名、"2 earlier messages" 等次要信息一律 400，不比正文更粗。
- **R-TY-3** 一个区域的文字层级不超过三级（标题／正文／辅助）。
- **R-TY-4** 标题比它下面的正文更重要，看上去也必须更重。
- **R-TY-5** 不使用全大写标签、字距拉开的眉标、斜体 UI 文字、Emoji 标签、中圆点拼接、装饰性序号。
- **R-TY-6** 中英混排的间距规则全局统一；中文行首不出现 `，。、；：！？）」`，行尾不出现 `（「`。
- **R-TY-7** 比较位置上的数字宽度稳定；四位以上的数字分组显示（131,072）。
- **R-TY-8** 偏好标签和表单标签不带冒号。`key: value` 只出现在折叠的原始诊断详情里。
- **R-TY-9** 不用缩小字号或调低对比来掩盖溢出。

### 3.4 颜色

- **R-CO-1** 配色由三部分组成：中性色梯度、一个强调色、语义色（成功、警告、错误）。第一阶段沿用 Qoder Bee 配色，按 §9 修正。
- **R-CO-2** 对比度（WCAG 2.x，按实际背景测）：
  - 承载信息的文字 ≥ 4.5:1；
  - placeholder ≥ 3:1，且不能被误认为已填写的值；
  - 输入框边界、焦点指示、图标按钮的图形 ≥ 3:1；
  - 禁用内容可以更低，但旁边必须有正常对比的原因文字。
- **R-CO-3** 语义色当文字用时，使用 §9 的文字变体；亮色原值只给图标、圆点和浅底色块。
- **R-CO-4** 强调色的实心填充一屏只出现一次（主操作）。选中态用中性选中底面。
- **R-CO-5** 链接在浅色和深色下都与正文可区分：链接色加下划线。
- **R-CO-6** 颜色只表达状态：日期、作者、普通元数据用中性色；破坏性动作用错误色系，和警告提示区分开。
- **R-CO-7** 同一状态在所有位置用同一种表现。
- **R-CO-8** 外壳背景（含渐变）上的文字仍要满足 R-CO-2，按渐变最不利的位置来测；tertiary 不用在外壳上。
- **R-CO-9** 悬停和按下只改变明度，不改变色相（例如黑色按钮悬停不变成绿色）。
- **R-CO-10** 浅色和深色分别调过：两边的层级、选中、警告同样清楚。

### 3.5 容器、线与形状

- **R-BX-1** 相邻区域使用同一种容器语言：主面板是圆角卡片，右侧详情和窄窗整页也是同样的卡片；不允许一个平铺、一个带框、一个是无外壳的白页。
- **R-BX-2** 一个章节最多一层框。不卡片套卡片，不每行一张卡，不彩色左竖线。
- **R-BX-3** 线只用一种粗细，只用来分组；能用间距分开的地方不画线。
- **R-BX-4** 圆角只有少数几档，全局不混用。
- **R-BX-5** 阴影只给浮在内容之上的东西（菜单、弹层、tooltip），一层、柔和。
- **R-BX-6** 不使用发光、毛玻璃叠层、多彩渐变；外壳渐变只能是很浅的背景，不能比内容更抢眼。
- **R-BX-7** 所有容器的外边距对称：主面板四周 margin 相同，顶部不贴窗口边缘。

### 3.6 按钮与操作的层级

- **R-BT-1** 操作分三级，在静止截图里就能分辨：
  - **主操作**：实心强调色，每屏最多一个；
  - **次操作**：有可见边框和底面的按钮；
  - **轻操作**：链接色文字或纯图标，只用于低频、上下文已经说清楚的动作。
- **R-BT-2** 以完成一件事为目的的页面（首用连接、新建事项、编辑资料、回答问题）必须有一个主操作。
- **R-BT-3** 文字按钮不能和加粗标签长得一样。
- **R-BT-4** 同类区域的关闭和返回方式统一：右侧详情一律用同一个 X 图标，整页一律用"← 返回"。
- **R-BT-5** 选中的图标按钮用中性选中底面，不用方形粗描边；选中、悬停、焦点三种样式互相可区分。
- **R-BT-6** 按钮宽度由文字决定；状态变化（Testing…、Saving…）不让宽度跳动。
- **R-BT-7** 点击区至少 32×32，且不挡住相邻控件。

### 3.7 图标与头像

- **R-IC-1** 全局只用一个图标家族；例外必须登记。
- **R-IC-2** 一个动作对应一个图标，一个图标对应一个动作：不同的导航项不用同一个图标。
- **R-IC-3** 图标尺寸只有两到三档（14／16／20），同一行内一致。
- **R-IC-4** 图标颜色跟随文字状态变化。
- **R-IC-5** 头像能区分对象：首字母加按名称稳定分配的底色，或真实头像；不能所有联系人共用一个人形图标。
- **R-IC-6** 状态角标形状清楚、语义单一，不压住主体，不像别的含义。
- **R-IC-7** 所有纯图标按钮都有 tooltip 和可访问名称。

### 3.8 状态与反馈

- **R-ST-1** 可交互控件都有 normal、hover、pressed、focus、disabled 五种外观且彼此可区分；适用时还有 selected、invalid、busy。
- **R-ST-2** 键盘焦点始终可见，且不落到视口外或被覆盖的区域。
- **R-ST-3** 同一屏只呈现一次同一提示。同一对象、同一效果的动作保留一个入口。不同对象的动作同时可见时，标签或所属区域须清楚标明各自作用于谁。
- **R-ST-4** 状态横幅不推开页面骨架，对象页头始终在顶部。
- **R-ST-5** 空态 = 一句事实 + 一个下一步。不拼接控件值，不写宣传语。
- **R-ST-6** 错误 = 发生了什么 + 怎么办 + 一个入口；原始详情折叠在后面。
- **R-ST-7** unknown、busy、已保存待应用、已测试、已应用外观各不相同。
- **R-ST-8** 加载时保持最终布局，加载完不整页跳动。

### 3.9 动效

- **R-MO-1** 只为状态变化服务：150–200ms，缓出。
- **R-MO-2** 不做装饰动画、逐项入场、脉冲、视差。
- **R-MO-3** 系统开启"减少动态效果"时取消位移动画。
- **R-MO-4** 流式输出、复制和保存反馈不推动周围内容。
- **R-MO-5** 拖动窗口改变大小时布局连续重排。

### 3.10 文案的视觉面

- **R-TX-1** 用户看到的文字里没有内部码、协议值、工程阶段用语（如 "during Pi integration"）、内部文件路径（如会话 `.jsonl` 路径），也没有 `Issue`／`Execution` 这类内部词。诊断详情除外，且必须折叠。
- **R-TX-2** 摘要和预览（联系人列表、历史结果）显示渲染后的纯文本，不露出 `[文字](链接)`、`**`、`##`、反引号等 Markdown 语法。
- **R-TX-3** 日期、时间、数字按界面语言本地化。
- **R-TX-4** 一句话能说清的不写成一段；说明只在能帮用户做决定时出现。
- **R-TX-5** 英文用 sentence case、动词开头；中文平实，用"你"。
- **R-TX-6** 中英两种语言在同一宽度下都不溢出、不截掉关键信息。
- **R-TX-7** 并列信息不拼成一个标签（"Ready: Assistant"）：状态和角色分开呈现。

### 3.11 溢出与响应式

- **R-RW-1** 任何宽度下都没有整页横向滚动；只有代码块和表格在自身内部横向滚动。
- **R-RW-2** 布局按**实际可用内容宽度**切换，不按窗口宽度：左右排列的行在可用宽度不足时改为上下排列。
- **R-RW-3** 长名称、长路径、长模型名截断时用省略号并有完整 tooltip；关键状态、错误和保存操作永远不被截掉。
- **R-RW-4** 无空格的长串可以断行，不撑破容器。
- **R-RW-5** 窗口变窄时先收侧栏、再收详情、最后才压缩正文；正文字号不变。
- **R-RW-6** 左上角控件避开 macOS 红绿灯区域，并保留可拖动的标题栏空间。

## 4. 页面标准

每个页面除第 3 节的通用规则外，还要满足以下要求。

### 4.1 联系人侧栏

- [ ] **V-RL-01** 侧栏是安静的背景；整栏只有选中行最突出。
- [ ] **V-RL-02** 标题、搜索框、列表行文字、底部设置共用左边缘（R-AL-4）。
- [ ] **V-RL-03** 每行最多两行：名称（13／500）和一行纯文本摘要或状态（12／400，secondary）（R-TX-2）。
- [ ] **V-RL-04** 未读数和需处理标记形状统一、对比合格（R-CO-2/3）。
- [ ] **V-RL-05** 行内不嵌套第二层白框。
- [ ] **V-RL-06** 底部设置行固定在底部，和列表有清楚分隔。
- [ ] **V-RL-07** 拖到最窄和最宽时内容都不溢出。

### 4.2 头像条

- [ ] **V-AR-01** 每个联系人一眼可区分（R-IC-5）。
- [ ] **V-AR-02** 选中、工作中、需处理的标记清楚且彼此不同（R-IC-6）。
- [ ] **V-AR-03** 新增和设置按钮使用同一种控件外观。
- [ ] **V-AR-04** 每项有 tooltip，键盘可达。

### 4.3 对象页头

- [ ] **V-HD-01** 联系人名 13／500、正文色，是页头最重要的文字；状态和角色 12／400、secondary，分开呈现。
- [ ] **V-HD-02** 右侧工具组图标同尺寸、同间距；当前打开的一项用选中底面（R-BT-5）。
- [ ] **V-HD-03** 计数或需处理角标不改变按钮尺寸，不和图标挤在一起。
- [ ] **V-HD-04** 页头始终在面板顶部（R-ST-4）。

### 4.4 对话

- [ ] **V-CV-01** 正文列居中、有最大宽度；消息、活动行、composer 共用左右边缘（R-AL-2/3）。
- [ ] **V-CV-02** 用户消息靠右，浅底色在两种主题下都看得出；Agent 消息是开放正文。
- [ ] **V-CV-03** 活动摘要是辅助层级：13／400、secondary，比正文安静。
- [ ] **V-CV-04** 同一发送者的连续消息间距小于换人时的间距。
- [ ] **V-CV-05** 消息操作在固定槽位，出现和消失不改变布局。
- [ ] **V-CV-06** 流式输出平稳增长；用户上翻后不被拉回底部。
- [ ] **V-CV-07** 空会话、加载中、加载失败、历史不可用各有设计过的呈现。

### 4.5 富文本阅读

- [ ] **V-MD-01** 标题层级差距肉眼可见；标题上方间距大于下方。
- [ ] **V-MD-02** 列表符号与文字对齐，续行与首行文字对齐。

## 7. 证据与记录

### 7.1 证据等级

| 标记 | 含义 | 能证明什么 |
| --- | --- | --- |
| **N** | 原生窗口观察（注明包、commit、数据状态） | 最终观感、字体、曲线、窗口 chrome |
| **H** | headless 渲染截图 | 布局、层级、颜色组合；不证明原生字体、点击区和动效 |
| **G** | 几何读数 | 辅助定位；不能单独证明视觉通过 |
| **S** | 源码核对 | 只证明用了什么；不证明渲染结果 |
| **未验** | 没看过 | 如实保留，不写成通过 |

- N 只对它实际观察到的那个主张成立。**一张静止的原生截图不能证明没有执行过的 hover、键盘操作、输入法组合、弹层开合或字体 fallback**；这类条目必须附上动作记录、前后截图或 AX 读回。
- 截图中的录屏工具光标和交互覆盖层不是 Nagi 组件。
- 同一 commit 不代表同一数据或运行状态；每条证据注明数据状态。headless seeded 与原生 fresh 不能互相替代，也不能把一个尺寸的截图标成另一个尺寸。
- 截图注明逻辑尺寸和缩放倍率，不从 Retina 像素反推 DIP。
- 缩小副本只用于总览。关于文字、细线、行内代码底块、颜色或像素的判断，必须看原始截图（可以只裁剪不缩放）或读取原图像素值。字体 fallback、输入法和数值对比度不能从缩小副本推断。
- §9 和 §10 的对比度是按色值计算的静态结果，不是从截图测得；截图中的颜色还受 JPEG 压缩和显示合成影响。

### 7.2 严重程度

| 级别 | 定义 |
| --- | --- |
| **P0** | 信息丢失或无法使用：操作被遮挡、错误被截掉、文字不可读、横向溢出、焦点丢失 |
| **P1** | 一眼可见的违反：对齐线错乱、容器语言不一致、按钮或链接认不出、同类页面骨架跳动 |
| **P2** | 细看可见：间距差一级、线粗不一、角标挤、个别字重不对 |
| **P3** | 精修：光学居中、换行位置、图标视觉重量 |

第一阶段按以下顺序判定，主单和 §12 共用此口径。

1. 有已确认的 P0 或 P1，候选判 **失败**。
2. 其余候选只要还有适用条目未验、证据缺失，或 P2 缺修复计划，均判 **待验**。未验项记录原因和补验场景。确实不适用的条目单列理由。
3. 适用项已查完、P0 和 P1 为零、每项 P2 均有修复计划，候选判 **通过**。已发现的问题仍按原级别保留失败记录。

**满分**另要求 P0–P2 为零、P3 均有结论，且 §2 七项检查全部通过。

### 7.3 记录格式

```
[规则或条目 ID] 页面 / 状态 / 宽×高 DIP @倍率 / 主题 / 语言 / 数据状态 / 证据(N|H|G|S，可并列) / 结果(通过|失败|未验|不适用) / 级别 / 原图与相关记录路径 / 说明
```

截图和原始证据放在 checkout 之外，PR 记录只写摘要和路径。

- [ ] 记录被检源码的 commit；候选已冻结，检查期间不改。
