# Xuhu Domain Glossary & Naming Standard

This document is the single authoritative domain vocabulary for Xuhu across product requirements, SQLite storage, Go/TypeScript wire RPCs, events, and model tool schemas.

## Canonical Entities

| Canonical Term | Status | Definition | Stable Identifier | Storage / Wire / Tool Anchor |
| --- | --- | --- | --- | --- |
| **Bot** | Shipped | A long-lived member of the Bot Team. Built-in `PandoraBox` and user Bots share one uniform model. | `botId` | SQLite `bots`, wire `bot.*`, tools `bot_*` |
| **Conversation** | Shipped | The continuous chat stream between the user and one Bot (current editable chat or read-only previous chat). | `conversationId` | SQLite `conversations`, wire `conversation.*`, tools `conversation_read`, `conversation_search` |
| **Activity** | Shipped | An independently tracked unit of work delegated to a Bot (e.g. researching a doc, implementing code, auditing a release). Persists across Bot switches and new chats. | `activityId` | SQLite `activities` + `activity_traces`, wire `activity.*`, tools `activity_*` |
| **Execution** | Shipped | One concrete model/runtime run inside a Conversation turn or an Activity start/continue cycle, with its own settlement and receipts. | `executionId` | SQLite `executions`, wire `execution.*` |
| **Question** | Shipped | A structured blocking question raised by an Activity when genuine human input is required. | `questionId` | Embedded on `Activity`, wire `question.answer` |
| **Material** | Shipped | Captured text snippets and file-reference snapshots attached to a Conversation draft or Activity. | `materialId` | `Draft.materials`, `Activity.materials` |
| **Memory** | Shipped | Strictly per-Bot lasting rules (L1.5), pending review learnings, and searchable dated work logs. | `ruleId`, `learningId`, `logId` | SQLite `bot_memory_*`, wire `memory.*`, tools `memory_*` |
| **Skill** | Shipped (M1 text + M3 OS-sandboxed scripts backend; UI handoff to `t1vb`) | A reusable playbook (`SKILL.md`, M1) with optional OS-sandboxed Node 22 scripts (`scripts/*.mjs`, M3); global, workspace-scoped, or Bot-authored. | `skillId` | Skill catalog + `bots/<botId>/skills/` + SQLite `skill_approvals`, wire `skill.*`, tools `skill_list`, `skill_read`, `skill_save`, `skill_delete`, `skill_test`, `skill_exec` |
| **MCP** | Shipped (M2 backend; UI handoff to `t1vb`) | A globally configured external service connector (`stdio` or Streamable HTTP), pooled by the worker (`shared` / `per_workspace` / `per_bot`) and mounted per Bot with scoped tool permissions (`all` / `readonly` / `allowlist`). | `serverId` | SQLite `mcp_servers` (nonsecret) + private `0600` `mcp-secrets.json` vault, wire `mcp.*`, event `mcp.changed` |
| **Session** | Shipped | A worker-supervised cross-turn stateful child process handle (`pty` via bundled Darwin `forkpty` helper or `pipe`) bound to an owning Bot and creating actor with a normalized, redacted 256 KiB UTF-8 ring buffer. | `sessionId` | SQLite `runtime_sessions`, wire `session.*`, events `session.changed` / `session.outputUpdated`, tools `session_*` |
| **Session Watch** | Shipped | A one-shot multi-condition asynchronous trigger (`exit`, bounded literal `match`, `idle`, `timeout`) armed against a specific `(sessionId, generation)` with atomic single-winner settlement. | `watchId`, `occurrenceId` | SQLite `session_watches` + `runtime_watch_occurrences`, tool `session_watch`, embedded on `session.get` / `session.list` |
| **Watch (`Timer` / `Schedule`)** | Shipped | Persistent UTC one-shot timer (`skip` or `fire_once_coalesced`) or IANA calendar/interval recurring schedule (`>= 10s` floor) with optional constrained `precheck` digest comparison. Restores strictly `restored` (`armed: false`). | `watchId`, `occurrenceId` | SQLite `runtime_watches` + `watch_occurrences`, wire `watch.*`, event `watch.changed`, tools `watch_*` |
| **Standing Watch Grant** | Shipped | Installation-local unattended observation grant binding exact `installationId`, `botId`, executable/skill digest, allowed arguments, canonical workspace, and minimum cadence. Never exported in backups. | `grantId` | SQLite `watch_grants`, wire `watch.listGrants` / `watch.revokeGrant` |
| **Bot Event Inbox** | Shipped | Durable per-Bot wake queue written in the same SQLite transaction as timer/schedule, `session_watch`, and `Activity` milestone transitions, with safe burst coalescing and at-most-once staged `bot_event_batches` claims (`dispatched=1` crash -> `unknown`). | `eventId`, `batchId`, `leaseId` | SQLite `bot_event_inbox` + `bot_event_batches` |
| **Orchestration Mandate** | Shipped (BG-3 backend; UI track `feat/orchestration-attention`) | A private, goal-partitioned autonomous wake scope keyed by `(botId, mandateId, targetConversationId)` running in `SessionManager.inMemory` generations with CAS checkpoints, `utility` routing, per-call metering, M4 admissions, and causal lack-of-progress backoff. Restores strictly `restored_readonly` (`dormant: true`). | `mandateId`, `runId` | SQLite `orchestration_mandates`, `orchestration_checkpoints`, `orchestration_runs`, `orchestration_admissions`, `orchestration_backoff`, wire `orchestration.*`, event `orchestration.changed` |
| **Orchestration Decision** | Shipped (BG-3 backend; UI track `feat/orchestration-attention`) | A non-blocking typed human decision card emitted by `orchestration_request_decision` (`needs_decision`) that releases the active provider slot while awaiting explicit approve/reject CAS resolution (`dormant: true` read-only after backup import). | `decisionId` | SQLite `orchestration_decisions`, wire `orchestration.decide`, tool `orchestration_request_decision` |
| **Conversation Notice** | Shipped (BG-3 backend; UI track `feat/orchestration-attention`) | A durable, draft-safe product timeline notice (`provenance: "orchestration"`) anchored `pre_send`, `post_settlement`, or `standalone` onto a Bot's immutable `targetConversationId` without mutating `conversation.history` or `Draft`. | `noticeId` | SQLite `conversation_notices`, `conversation_timelines`, wire `conversation.timeline`, event `conversation.timelineChanged`, tool `conversation_notify` |

## Naming Conventions

- **JSONL Wire RPCs & Events**: `<domain>.<verb>` in camelCase for both method names and payload fields (e.g. `activity.list`, `conversation.saveDraft`, `memory.reviewLearning`, `execution.settled`).
- **Model Tool Names & Inputs**: `<domain>_<verb>` sorted alphabetically for KV-cache determinism, with `snake_case` input parameters (e.g. `memory_save_rule`, `bot_inspect_team`, `activity_get(activity_id)`).
- **UI Terminology**: Use **Bot Team**, **Bot**, **Materials**, **Activity**, **Previous chats**, **Settings**, and **Memory & Learnings** consistently; localized display strings live exclusively in `locales/`.

## Retirement of Legacy `issue` Terminology

The term `issue` was an early storage name for **Activity** and is retired as a product concept.

- **Allowed read-only historical scope**: Legacy `issue` fields remain strictly confined to read-only historical admission and transcript readers — specifically the v10 `contacts.json` decoder (`internal/store/store.go`, `internal/pi/worker/product-profile.ts`), retained v1 import metadata, and historical Pi transcript readers (`readImportedActivityResult` and `xuhu.issue_tools.*` filtering in `internal/pi/worker/product.ts`).
- **Migration status ([RFC-0001](../rfcs/0001-multi-brain-and-capabilities.md))**:
  - **M0a (Shipped)**: Live model tools use `activity_delegate`, `activity_list`, `activity_get(activity_id)`, `activity_action(activity_id)`, `activity_ask`, and `activity_trace_read` with zero dual live aliases.
  - **M0b (Shipped)**: Live Go runtime types, fields, and files under `internal/app/` are normalized to `Activity` (`activities.go`, `activity_results.go`, `activity_supplement_view.go`, `activity_tool_views.go`), unused pre-Pi `IssueToolDefinitions` / forwarding DTOs are retired from `internal/store/tool_contract.go`, and v10 legacy `StoredIssue` admission & recovery remain intact.
