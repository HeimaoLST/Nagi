# Subsystem: GUI Workbench

## Responsibilities and boundaries

- `internal/app` composes the Bot Team rail, current chat and composer, collapsible right-hand `detailProfile` drawer (Bot Profile, Scheduled work, Background work and Terminal sessions), Activity drawer, status notices, Previous chats, Settings and dialogs. Secondary click anywhere in a Bot Team row or choosing the header's borderless `···` (`Bot overview` / `Bot 概览`) menu opens management for that Bot's stable ID. Settings holds global preferences.
- `internal/theme` supplies the Workbench and Settings palettes, shared controls and layout metrics. `locales` supplies English and Simplified Chinese text. User text, Bot names and model names retain their original content.
- MyGo owns the native window, main-thread rendering, focus, scrolling, IME and system integration. `internal/app/app.go` brings up the product runtime and routes app exit through the worker drain. Go owns view state and user intent. The TypeScript worker owns product state and execution admission, and Pi owns execution and transcripts. [Product protocol](../design/product-protocol.md) · [Desktop design](../design/desktop.md)

## Primary execution paths

- `view` resolves the current theme and lays out the Workbench. `bindBotRowMenu`, `botOverviewButton` and `profileDetail` address the Bot recorded when management was opened. `openProductProfile` preloads initial active orchestration and Terminal sessions summaries synchronously and `updateUI` / `setUIHook` serialize pre-hook callbacks via `directUIMu` before pump attachment. `chat` composes the message list, Activity drawer, autonomous decision strip (`orchestrationDecisionStrip`) and composer. `productTimeline` reads paginated `conversation.timeline` items (falling back to `productHistory` only for unsupported BG-2 workers), interleaves committed `msgNotice` rows and falls back to durable notices with a warning if the transcript fails. `latestReadUserMessageIndex` shows a localized `Read` / `已读` indicator below only the latest Bot-received user message while skipping `msgActivity` and `msgNotice` rows until a visible Bot reply appears. `sendProductConversation` saves and submits the exact draft revision, surfaces queued capacity waits (`sendQueued` with pre-dispatch Stop and preserved draft while withholding `Read`), and reconciles receipts on `execution.started`, `execution.settled`, `orchestration.changed` or reopen without auto-replaying mutations. [Workbench](../../internal/app/view.go) · [Navigation](../../internal/app/navigation.go) · [Product bridge](../../internal/app/pi_app.go)
- `openBackgroundWork`, `openBotSessions`, `openBotScheduledWork`, `openDockBotPanel` and `openDockBackgroundWork` open Bot-scoped inspectors inside the adaptive `detailProfile` drawer (`>= 900 DIP` side-by-side with chat; `< 900 DIP` in-app page with Back, revealing `productConversationsView` for Source chat and restoring the inspector on Escape), showing wake metrics, backoff, run history, action receipts and guarded `Stop` / `Decide` / `Kill session` operations with opener focus restoration (returning directly to chat and closing the drawer on root Back/Escape unless opened from inside Bot Profile). Inside Background work (`orchestration_ui.go`) and timeline notices (`conversation_timeline.go`), summary cards, decisions, operation states and wake telemetry compose DS 2.1 `StatusPill`, `InlineBanner`, `SkeletonLine`, `SparklineStatTile`, `ContextCapacityBar`, `SegmentedActivityChart7D` and `WakeRhythmStrip24H` primitives. `refreshProductActivities` and `openProductActivity` bind reads to the captured Bot and Activity. Returning through Back or escape restores the corresponding surface and its source control. [Activity and history](../../internal/app/workspace.go) · [Orchestration UI](../../internal/app/orchestration_ui.go)
- `openSettingsTab` records `settingsReturnFocus` from the `settingsSource*` opener only on first entry. Tab changes keep the original return target. `closeSettings` restores the matching rail, profile, connection, configuration, composer or auxiliary control. For a focused Markdown link, `captureLinkSettingsSource` records its document and link identity. `finishMarkdownLinkReturn` restores the exact link if it still exists, with one fallback to the active surface when it has disappeared. [Settings navigation](../../internal/app/settings_page.go) · [Link focus](../../internal/app/view.go)
- `chooseDataRecovery` selects and inspects the file, then the active preview presents the captured copy and its scope before `confirmDataRecovery` rechecks the target. The original bytes are preserved before installing a compatible recovery copy. The UI distinguishes failed install, verified install and unconfirmed readback. [Recovery flow](../../internal/app/settings_page.go)

Closing the native window hides the existing Workbench and keeps the owned worker, armed watches and sessions running. Dock activation shows the same window with its current Bot, drafts, Materials, quote and scroll positions. The Dock also opens Scheduled work, Background work and Terminal sessions for the selected Bot. Explicit Quit shows the shutdown status, fences admission and drains the worker before closing the window. On OS logout or shutdown, the app saves its UI state and synchronously reaps the worker within a bounded shutdown attempt. [Native lifecycle](../../internal/app/native_lifecycle.go)

## Layout, theme and focus invariants

- At `1440 × 900`, the full Bot Team rail, chat and Bot Profile can coexist. Full rail layout starts at `1180 DIP`. From `900` through `1179 DIP`, the open profile uses the compact avatar rail. Below `900 DIP`, the profile becomes an in-app page with Back. At the default `1040 × 720`, content keeps its centered reading column. At `960 × 640` with the profile open, the editable composer must retain at least `440 DIP` of net width. At the `720 × 640` minimum, the composer remains usable with Activity detail open. [Breakpoints and geometry](../design/desktop.md#adjustable-layout-values) · [Native matrix](../design/ui-checklist.md#native-v1-review)
- Settings uses a `248 DIP` sidebar, an `820 DIP` centered content column and a full-width scroll viewport. Below `640 DIP`, the sidebar uses wrapping top navigation. Back and category rows use intrinsic square icon slots and the shared control radius. The General and Advanced preference subtitles wrap with the available content width. Recovery confirmation occupies its own card below the backup controls. Preserve source focus and active scroll when changing appearance or language.
- `resolveAppearanceTheme` resolves system, explicit or imported preferences to a `theme.WorkbenchTheme` containing the MyGo `ui.Theme`. `theme.SettingsTheme` derives Settings surfaces and checks contrast. `theme.TransitionControl` applies a palette change on the first frame and keeps hover and press transitions within one palette. `internal/theme/ds2.go`, `internal/theme/theme.go`, and `internal/theme/charts.go` provide DS 2.1 optical controls (`DrawFocusRing` 3-DIP air-gap rings, tactile elevated buttons including `DangerSolidButton`, recessed inputs with outer focus halos, `Checkbox`/`IndeterminateCheckbox`/`Radio`/`Slider`/`StatusPill`/`InlineBanner`/`SkeletonLine`/`BrandPedestalIcon`, and scheme-A analytics charts), while `botStatusAvatar` implements Hybrid Status C pedestals and dynamic background-cutout corner badges. `setLanguageMode` applies MyGo's locale and localized UI uses the current render locale. [Appearance](../../internal/app/appearance.go) · [Settings](../../internal/app/settings_page.go) · [DS2 controls](../../internal/theme/ds2.go) · [Charts](../../internal/theme/charts.go) · [Palette](../../internal/theme/theme.go)

## Failure modes and compatibility

- Keep each draft, Material, execution, question and result bound to its recorded Bot and target. A lost or stale reply triggers readback of its recorded identity. Unknown delivery stays visible and is never replayed on reopen. Focus recovery restores a control on the current surface when the original target no longer exists.
- Read-only history and diagnostics remain accessible when their data is available. A failed backup or restore keeps recoverable data and reports the actual outcome. Opening a restored profile does not dispatch pending work. [Profile admission](../design/product-protocol.md#current-profile-admission)
- The visual hierarchy uses neutral surfaces, semantic status ink, hairline input borders and one filled primary action per surface. Keep preference and diagnostic actions intrinsic. Use disclosures to keep secondary information out of the main action path. [Code and UI standards](../code-standards.md)
