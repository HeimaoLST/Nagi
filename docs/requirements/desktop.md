# Nagi 桌面产品需求

<a id="v1"></a>

## v1 的用户操作

用户配置连接，创建长期使用的 Bot，在对话里交办工作。同一个 Bot 可以同时负责多项工作。用户能分别查看进度、补充资料、回答指定问题、停止指定执行并取回结果和文件。切换 Bot 后工作继续，重开后可以核对原来的工作和发送状态。

Bot 内可以找回旧对话，活动能打开来源对话。读取历史不调用模型。未确认的发送保留原状态，由用户核对。连接的测试、保存与应用各有明确结果。具体接口见[产品协议](../design/product-protocol.md)。

当前版本沿用联系人资料入口和「保存并开始新对话」。资料表单已有的字段属于实现现状；新增字段、角色关系或管理页面需有对应的用户操作依据。旧 Saki 导入与兼容、独立事项抽屉和旧页头按钮、跨对话全文搜索、原始工具日志浏览、外部 MCP 配置、退出后继续运行及通用调度已退出 v1 范围。

下列专题保留已采用的视觉、设置和恢复要求。窗口布局以[当前视觉约定](../design/desktop.md#qoder-complete-layout-20261116)及[已批准的第一阶段修正](../design/ui-checklist.md)为准。Pi 负责执行与会话记录，当前资料格式及恢复边界见[产品协议](../design/product-protocol.md#current-profile-admission)。

## Qoder 完整 UI 与布局基准（2026-11-16，当前最高视觉约束）

用户最初要求 **UI 完全参考 Qoder，先不建立 Nagi 自己的风格**，随后批准了 [UI 检查单第一阶段](../design/ui-checklist.md#9-第一阶段下限修正已决定)的全部可读性、层级与布局修正。现行要求是保留 Qoder 基础并实施这些修正，具体数值与页面组合统一写在[当前视觉契约](../design/desktop.md#qoder-complete-layout-20261116)；第二阶段自有风格仍只是提案。本节及对应现行设计取代旧 QD／PREF 中冲突的数值，既有实现与验收记录保留为历史。Nagi 产品名称与联系人／事项／Runtime 能力保持既有语义，不复制 Qoder 的账号、任务模式或权限能力。

- 参考现场为已安装Qoder CN 0.4.8／f8c98a、Bee／Sans／Standard。容器、控件、排版与色彩沿用已核参考及用户批准的第一阶段修正，不逐页自创替代样式。只映射Nagi真实存在的功能，不新增Qoder功能来凑外观。
- 侧栏不重复显示 Nagi 名称，不再提供活跃／已归档／全部筛选。联系人使用一个可搜索列表；既有归档标记、只读／恢复与发送限制仍由联系人资料管理，不因移除筛选而清除记录。
- 页面先定义完整布局契约：侧栏、主面板与滚动视口分别明确宽度；内容的最大宽度在满宽视口内生效；导航组填满侧栏且共享文字／图标对齐线；同页嵌入的表单共享分区边界，不能按最长文字各自收缩。
- 必验实际组合为：已有联系人／会话、已保存默认连接、已展开连接高级设置，以及中段滚动；同时检查720×640、1040×720及宽窗口，中／英、浅／深色。验收内容包括整体对齐、主区边界与滚动条位置，不能仅以控件可达、截图数量或 CI 绿证明页面合格。
- 保留原Draft／Save／Test／Apply、精确整数、scope、unknown／不重放、取消、恢复与退出drain。视觉修正不改变业务行为。自定义主题仍为用户显式选择的覆盖，不改写已存选择；内置默认采用Qoder基础及第一阶段修正，旧内置ID继续可读。
- 每个完整页面有一个集成验收负责人，组件作者的局部通过不替代页面组合通过。交付分别报告实现／CI／包与实际整页原生验收状态，未检查的组合保留待验。

### PREF-AC1–PREF-AC7

1. **PREF-AC1（通用偏好）**：Given 外观／主题／语言当前值、主题缺失／导入取消及真实偏好保存失败；When 查看、键盘选择或重试；Then 同组行显示准确枚举和当前值，外观仍立即应用并经现有 store 尝试保存，失败不回滚已生效选择，保留未保存提示与 Retry save；语言仍走既有 MyGo SetLocale／系统偏好路径和局部系统窗口重启说明，不新造保存失败通道。主题选择条件、requested ID／同类回退／警告、导入不自动选中、registry／store／取消与 I/O 归属均不变；仅渲染行不调用 setter。
2. **PREF-AC2（首用可完成）**：Given 尚无有效已保存受管连接或已有配置不可读取；When 首次进入连接设置并填写／校验；Then endpoint、遮蔽 key、model 三个必需自由文本输入直接可见，协议与文件夹选择可发现，目录必须由用户显式选择／确认，不能把启动 cwd 当选择。合法草稿才进入原显式动作；无效字段及完整错误可到达并聚焦，不能靠填写了部分值就切到已保存展示。720×640 自然滚动后所有必要控件可用；取消不改目录，不产生请求。
3. **PREF-AC3（已存先读）**：Given 有有效已保存连接且表单静止、未改、无错误及待处理编辑；When 打开设置；Then endpoint、key、model 以标明来源的已保存值行呈现，不常驻自由文本表单，key 仍遮蔽；显式 Edit 在原行打开带标签的同一草稿字段。协议保留紧凑枚举；默认配置、实际已应用、已保存待应用及当前对话保持各自事实，不把已存值冒称当前会话值。
4. **PREF-AC4（编辑不丢失）**：Given 已打开、未保存、无效、错误或异步动作中的原表单；When 收起／重开 Edit、切分类／返回，或保存／应用回调改变其他事实；Then 原始字符串、同一表单归属及必要反馈保持，布局不得重建／ResetDraft、用 saved/effective 覆盖草稿或空值替换 key。收起不是 Discard；收起的草稿仍明确未保存／无效，错误不能消失，编辑可直接恢复；校验自动展开并聚焦相关字段／Limits。原显式动作仍按既有语义更新 initial／反馈，只有显式 Discard 执行原 ResetDraft。
5. **PREF-AC5（动作与作用域）**：Given 已保存、已应用、当前会话与当前草稿彼此不同；When 渲染／展开／修改、显式 Test、Save configuration、Save and apply 或 Apply saved；Then 前三类呈现操作零模型／任务请求，Test 只捕获完整当前表单且可能计费、不 save/apply，Apply saved 只用 host 已保存值；保存失败不应用，保存后应用失败只重试应用，活动／Busy 等准入不变。RP2 整体测试失败文案、一次当前表单回调、历史／ID／旧会话和不自动重发语义保持。
6. **PREF-AC6（精确数值与目录）**：Given token／任务数字符串含空白、正号、非整数、后缀、空值、host-int 溢出或边界值；When 输入、校验或点击任务数 stepper；Then 继续使用 `strconv.Atoi(strings.TrimSpace(...))` 的原精确整数规则与错误，原无效文本不被 coercion／clamp／默认值替换；context／output 为精确输入，保持正数、output<context、context-output≥4。任务数只在当前文本为可表示正整数且 ±1 结果仍合法时改草稿，1 的减与 int 上界的加不改值；不新增产品上限或 provider 并发承诺。普通目录行显示值＋选择器，手输绝对路径仅经明确进阶入口，仍是同一草稿与原校验／选择后显式 Save／Test／Apply 边界。
7. **PREF-AC7（相邻边界与可用性）**：Given 中／英文、Paper／Moss、720×640／1040×720、长值／错误、真实本地保存失败及 chooser／C8 活动；When 键盘／焦点导航、返回、取消、迟到回调或正常退出；Then 标签／状态／必要 Details 与动作可发现、可滚动且不截掉完整错误，视觉字号／间距／图标／控件面按 QD-01–QD-10，真实命中与焦点按 QD-06 单列验证，保留 Paper／Moss 语义色；原本地保存焦点／选择、单一 Settings/store、密钥去密、C8 准入／结果／未保存文字退出警告、AD 匹配可见确认、unknown、busy/no-queue、chooser 归属和 I/O drain 不变。源码、headless、真实原生／IME／AX／文件选择与独立用户证据分开，截图／HTML 不替代行为或原生通过。

## 产品定义

**Nagi 是一个开源的、以长期 Agent 联系人为核心的桌面工作台。用户通过持续对话交代事项，联系人理解意图、组织工作并自主推进；用户可以随时补充要求、了解进展或深入参与具体执行。**

产品以 Grok Bot 式的完整使用体验为参照。开源和好用本身构成当前产品方向，不以发明竞品没有的交互为前提，也不承诺复制竞品全部功能、服务或性能。源代码开放如何对应许可、安装、分发和部署方式，需分别落实，不能从“开源”直接推导为任意模型可用或无需配置。

首批试用由维护者及朋友参与；**产品面向所有人，包括非程序员**。面向需要持续委派工作、减少逐步指导负担的人；编程、资料整理和研究都可以成为使用场景，当前未冻结单一垂直领域。代码阅读、文档整理和登录接口只是讨论／验收示例，不表示用户已经选定全部首批试用任务。

主要价值是：用户能找到持续负责的联系人；交代的事情可被跟进；执行中能继续交流；成果和未解决问题可检查。安装、配置、首次委派、补充要求、获取结果与后续继续应形成可用流程。

**这是明确的产品要求，尚未实现和完整验收。** 正常支持范围内的安装后配置、验证和恢复必须通过明确、合理的 GUI 设置与默认值完成，**终端命令、环境变量、手改配置文件均为零步**。该标准覆盖所有相关配置，不以修正某一个 context 环境变量或测试 fixture 代替。当前实现盘点与首批三个实施切片见 [配置体验交接](../design/desktop.md#consumer-configuration-20261110)。工程／测试可以显式指定受控 Pi 输入，不成为普通用户的前置或必需恢复说明。

| C8 | **恢复有入口和边界**：连接／凭据错误、目录失效、保存／应用失败、helper 缺失、数据不可读和断连未知均有简明事实与 GUI 下一步（修正、重试、核对历史、打开位置或图形化重开／重装指引）。正常支持的可恢复故障须完成端到端恢复；数据损坏须保留原件并提供经明确选择的恢复路径，无有效副本时如实说明不能恢复，不以手改 JSON／数据库作为解法。副作用或持久化未知先核对，不自动重发，不把受理当完成或把执行完成当事项完成。 |

## C8：工作台数据恢复副本与暂停恢复（有界规范草案 v2，2026-11-11）

当前 Pi 版本只支持本版本 Nagi 工作台的备份和恢复。安装从独立的 Nagi 资料目录开始，旧 Saki 数据、历史、配置和执行记录已退出产品范围。下文的历史设计和验收结果按当时的版本解读。

**本节细化 C8／MVP-10，不表示已经实现或完成 C8。** lead 已确定本片方向：在唯一 Settings／数据不可用提示中提供显式 **Save recovery copy…／保存恢复副本…** 与 **Restore paused…／恢复并暂停…**；规格须经冻结评审、由 lead 接受后另行授权实施。现有 v9 没有数据导出／恢复入口，Restore contact 只是取消联系人归档。正常使用全程零 CLI／env／手改文件；不新增备份服务、自动备份／轮换／调度、第二个 store、迁移框架或自动重试。C1–C8、完整 MVP-01–12 及已接受 RP1／RP2 原文与边界均保留。

**范围与副本来源**：保存的是已持久化的 Nagi 工作台数据：联系人／资料／已存草稿／归档、事项／要求／问题／执行快照、资料快照／待发送意图、补充与应用工具账本、既有 ID／会话引用、布局／外观／所选主题 ID。**不包含**未保存编辑、Runtime 消息／工具历史／session 数据、模型或提供方状态、connection.json 的设置／密钥、主题文件、实际工作文件、应用程序及系统语言偏好。副本不是完整工作或 Runtime 备份，不保证引用的历史仍存在或适配当前连接；缺失时只能如实显示不可读取，不补造历史／session。

普通用户通过新“保存恢复副本”选择目标文件夹，得到可直接再次选择的完整文件；也可选择自己已有 OS／文件备份中的兼容 Nagi 原件。没有现成副本时当前版本不能凭空恢复；不得要求用户编写 JSON、寻找隐藏配置后手改、或暗示现有备份／导出功能。每次只保存一个明确时点的已存数据，不承诺覆盖后续编辑或 Runtime 变化。

## RP1／RP2：恢复提示与实际操作一致（规范，2026-11-11）

| 对话交付未知，连接可核对且已有 session | 使用对话的 Reload／重新加载。诊断为空或为非空 send-protocol／send-delivery 时，均能找到并用键盘触达该既有读回动作。 |
| 事项工作交付未知，连接可核对且执行关联有效 | 使用事项 Check run／检查执行及 `supplementUnknown`，不以对话 Reload 代称；保留既有读回与准入条件。 |
| 任一域交付未知，连接 failed／exited／其他非 ready，或 ready 但无 client | 使用 `sendDisconnectedState`：保存／复制未保存文字、图形化重开 Nagi、再核对历史；不保证重开即恢复。普通摘要及退出产生的 status-connection-lost 不指示此刻选择 Reload／Check run。对话无可用 Reload；事项既有 Check run 禁用，相邻原因可读，点击／键盘均不发起 RPC。 |
| 事项执行缺可信 SessionID 或 TaskID（即使 ready） | 不推荐 Check run；按钮禁用并说明没有可核对的任务关联记录。保留已有详情／历史导航；重开不补造关联。“确认未派发”仅在原有条件允许时保留，不自动确认／重建／重发。错误归属同样不准核对。 |
| prepared／明确未派发／rejected／真实执行失败／连接不匹配 | 保持各自含义、恢复入口与门槛，不统称断连／未知／测试失败，不解除原有发送／更新限制。 |
| connErrorTestFailed：测试前准备、请求阶段或请求后清理出错 | 使用中立的整体测试过程失败摘要，Details／详情披露原有有界、去密诊断。可编辑当前表单并显式再选 Test connection and model／测试连接与模型；沿用可能计费及不 Save／Apply 的提示。不推断模型请求失败，也不推断没有请求／费用。 |

RP2 摘要固定为 en **“Connection and model test did not complete successfully.”**／zh **“连接与模型测试未能成功完成。”**，只用于 connErrorTestFailed，真正已分类的认证／模型／执行失败保持原含义。事项缺少关联时使用 en **“Nagi has no verified record of which task to check. Review the existing run details and history before continuing; nothing will be resent automatically.”**／zh **“Nagi 没有可核对的任务关联记录。继续前请查看已有执行详情与历史；不会自动重发。”**；断连时先说明连接不可用，不承诺重开能修复关联。

普通摘要表达当前可行操作；原始诊断在明确的 Details／详情中按现有有界、去密规则展示，标作技术记录。其历史 Reload 字样不改写，也不作为当前动作承诺。呈现、披露、导航或语言切换不重写原始 send/status/execution/test 错误、ID、未知状态、草稿、发送快照和历史。恢复呈现不自动 Test、提交执行 或重放；显式核对只进入既有读回路径，状态解除与后续准入仍由既有可信读回规则决定。

### 验收条件（Given／When／Then）

1. **RP-AC1（对话）**：Given 已关联对话且交付未知，诊断分别为空、非空 send-protocol、非空 send-delivery；When 在 en／zh-Hans 查看 failed、exited、ready 无 client、ready 有 client；Then 所有普通提示与 Reload 可用性符合上表，包括退出的 status-connection-lost；可核对时保留可触达的 Reload，无矛盾的第二条指引，不能只检查主状态行。
2. **RP-AC2（事项）**：Given 同样的未知交付／连接／诊断组合及有效执行关联；When 查看事项卡与执行记录；Then 可核对时推荐事项 Check run 且可用、键盘可达；不可核对时按钮禁用、原因可读，尝试激活无 RPC／错误回写，不混入对话 Reload。空诊断也有准确指引。
3. **RP-AC3（缺少关联）**：Given 事项执行缺 SessionID 或 TaskID，或执行不属于当前事项；When 查看、尝试 Check run 或导航已有详情／历史；Then 不承诺可核对、不调用读回、不改写执行记录，导航及原有“确认未派发”条件保持，不自动确认或发送。
4. **RP-AC4（记录与读回）**：Given 实际 headless protocolFailed／applyRuntimeExit 产生两域未知及非空诊断；When 渲染、展开／收起详情、切换语言、导航或连接变为 ready；Then 原始错误／状态详情、关联 ID、未知状态、草稿、发送快照和历史保持，密钥不外露，自动 Test／提交执行 与呈现引发的 RPC 增量为零。显式 Reload／Check run 仅走既有读回；可信结果才按原规则更新，失败／陈旧结果不擅自解除未知或重放任务。
5. **RP-AC5（相邻语义）**：Given prepared、not-dispatched、rejected、failed、connection mismatch 或模型更新待核对；When 显示／披露恢复或显式核对；Then 各分类及原有活动工作、归属、revision／读回准入保持，不把 accepted 当完成或把执行完成当事项完成，不增加任务重试入口或自动发送。
6. **RP-AC6（整体测试错误）**：Given 当前表单 Test 回调返回 connErrorTestFailed，分别以请求前准备／启动／ready 和响应后清理错误为代表；When 显示失败；Then 两语言均为上述中立摘要，不称模型请求失败或从未请求，原诊断可披露；真正已分类的认证／模型／执行失败保持独立语义。
7. **RP-AC7（显式测试与状态）**：Given 已保存且待应用的设置、不同的当前草稿及已有联系人历史；When 显式 Test 一次、查看详情、再显式 Test 一次；Then 每次只回调一次并传入当时完整表单，计费提示可读；详情、导航、失败展示不再次 Test、不 Save／Apply，不改变草稿、已保存／待应用状态或历史；ErrorDetail 原件不改写、展示去密，新的显式 Test 重置旧披露状态。
