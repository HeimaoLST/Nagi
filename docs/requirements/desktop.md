## v1 用户流程

用户在左侧 Bot Team 列表中管理自己的 Bot，并与它们长期对话。一个 Bot 可以接多项工作，每项工作保留自己的进度、问题、执行和结果。用户切换 Bot 或开始新对话后，已经交办的工作继续运行。

| 用户操作 | 可观察的结果 |
| --- | --- |
| 首次配置连接 | 在设置中填写地址、密钥、模型和工作目录。用户显式触发测试，可以分别确认保存和应用的结果。 |
| 创建和维护 Bot | 从左侧 Bot Team 列表添加 Bot。右键某个 Bot 所在的整行，打开该 Bot 的管理菜单，编辑资料、归档或恢复。管理操作绑定到点击的列表项，与当前对话独立。设置页只管理全局选项。 |
| 打开或重开应用 | 恢复所选 Bot、当前对话、草稿、已保存材料及活动状态。读取历史不调用模型。 |
| 发消息或停止回复 | 当前 Bot 的草稿可以包含文字与材料。发送后显示流式回复。停止只作用于所选对话的本次执行。 |
| 在对话里交办和跟进 | 用户可以交办多项任务，查看进度、补充材料、回答指定问题或停止指定执行。每项操作对应具体活动，其他活动可以继续。 |
| 找回旧对话和结果 | 「保存并开始新对话」保留旧对话。用户可以从 Bot 的旧对话列表或活动的来源入口打开只读历史，按执行查看结果和文件，再回到当前草稿。已有跨 Bot 委派的结果归回发起方。 |
| 断线后核对、退出 | 用原操作标识核对状态和历史，无法确认的发送保留为未知，不自动重发。退出时应用收尾并回收子进程。 |

## 资料恢复

用户在设置中保存当前工作台的恢复副本。运行中的执行阻止导出。已持久化的未知发送可以备份。当前资料损坏时，用户预览副本并确认恢复；替换前保留损坏原件。重开后可核对 Bot、草稿、材料、活动和回执。会话正文与结果文件分别依赖原 Pi 记录和工作目录，连接密钥由独立文件管理。

Go、TypeScript 与 MyGo 的接口和数据边界见[产品协议](../design/product-protocol.md)。窗口布局、焦点、滚动、主题和语言由 MyGo 管理，见[桌面视觉约定](../design/desktop.md)。
